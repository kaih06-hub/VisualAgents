# VisualAgents README-graph check, set 9 (2026-10-26)

Ten agent projects that draw their agent graph in the README were scanned with `visualagents scan --static`. None of
them appears in sets 1-8 (80 projects). Each map was scored against the README graph. The failures were then traced
to code shapes the scanner did not understand, and those shapes were fixed with general rules on `dev-refinement`. No
rule names a project. All 80 projects of sets 1-8 were re-scanned before and after to check for regressions.

Ground truth is in `ground_truth_set9.py`. It was written from the README diagrams, and from the names the source uses
for each drawn box, before any scan, and was not edited afterwards. Raw scores are in `results-set9-2026-10-26.json`.

"Before" is `dev-refinement` at `99d87d6`, which is the set-8 work handed off as a bundle on 2026-10-25 (not on
`main` yet). "After" is this change, committed on top of it.

## How to read the numbers

- **Matching rate (node recall)**: the share of README components that appear on the map.
- **Correct rate (node precision, strict)**: the share of map blocks that are README components. The lenient version
  also accepts blocks that exist in today's code but are left out of the drawing, such as the human-in-the-loop
  handlers of agents-from-scratch or Contoso's article evaluators.
- **Code recall**: the matching rate, leaving out drawn components the code doesn't have as agents (`readme_only`):
  LLMCompiler's task fetching unit and executor run no model, and MACRec has one Analyst class for both drawn analysts.
- **Edge recall / precision**: the share of README arrows found, and the share of map arrows that are README arrows.

## Differences per project, and why

**GPT Newspaper.** All ten boxes were found before and after. The one missed arrow was reporter → assignment: the
`reporter` node runs the article graph inside its function (`await article_graph.ainvoke(...)`), and
`article_graph = build_article_graph()` was not recognised as a compiled graph because the compile happens inside the
builder function. Both graphs also use a builder variable called `builder`, which made their ends indistinguishable.
*Now* a graph compiled by a builder function is a subgraph, and each builder keeps the entry and exit nodes of its own
function. Edge precision dropped to 0.92 only because the map now also draws designer → reporter (the subgraph
returning), which the README leaves implicit.

**agents-from-scratch.** The real graph (triage router → response agent → llm_call ⇄ environment) was found before and
after. The wrong blocks came from the tutorial notebooks (`langgraph_101.ipynb`, `agent.ipynb`), which rebuild toy
graphs (`step_1`, `human_feedback`, `write_email_node`). *Now* notebooks that walk through a package which wires its own
agents are treated like `examples/`. The remaining strict-precision gap is real code: the human-in-the-loop and memory
variants of the same graph (`interrupt_handler`, `mark_as_read_node`) and the cron ingest graph are separate entries in
`langgraph.json`, so lenient precision is 1.00.

**Contoso Creative Writer.** Before, the map had one block, `my_assistant`. There were three separate problems:

- the writer, product and editor agents ask the model through Prompty (`prompty.execute("writer.prompty")`,
  `Prompty.load(path)(...)`), which was not a recognised model library;
- the researcher is an Azure AI Agent Service assistant created as `create_agent(name="my-assistant")`, a tutorial name;
- that one framework agent made the scanner skip the plain-model-call pass for the whole project;
- the orchestrator calls each agent through its module (`researcher.research(...)`, `writer.write(...)` after
  `from agents.researcher import researcher`), which run order did not follow.

*Now* Prompty / promptflow calls are model calls and a `.prompty` file is the function's own prompt; the placeholder
name gives way to the file (`researcher`); a thin framework layer (one or two agents that nothing wires) no longer
hides the project's other model callers; and `module.function()` calls are followed. All four agents and all three
arrows are found. Edge precision is 0.50 because the map also draws what the code does and the drawing leaves out:
researcher → product (the order `orchestrator.create()` runs them in) and the editor's feedback loop back to the
researcher and writer. Strict precision is 0.57 because the article evaluators (`evaluate/`) are model callers too.

**Reflexion.** Before, only `ReactReflectAgent` from the HotpotQA sub-project was found: a project class named `*Agent`
counted as a framework agent and switched off the plain pass, so the programming sub-project's generator
(`generic_generate_func_impl`, `generic_generate_internal_tests`, `generic_generate_self_reflection`) was never looked
at. *Now* the thin-framework rule brings them in, and a method that only hands over to one agent (`gen.func_impl()`)
stands for that agent, so the run loop in `reflexion.py` links them. The missed evaluator → self-reflection arrow goes
through the test executor (`exe.execute`), which is not a model call: the map shows internal-test generation → actor →
self-reflection → actor. Strict precision is 0.56 because the repository holds four separate experiment programs
(ALFWorld, WebShop, HotpotQA, programming), whose trial drivers are on the map too.

**LLMCompiler.** Before, the map showed two LangChain agent classes (a copied `StructuredChatAgent` and the ReAct
baseline) and none of the system. The planner asks its model as `await self.llm.apredict(...)` where `self.llm` is a
constructor parameter typed `BaseChatModel`, which no rule followed. *Now* typed model parameters and LangChain's older
calls (`apredict`, `agenerate_prompt`) are model calls, and the copied LangChain `Chain` / `LLMChain` /
`AgentExecutor` classes in `src/chains` and `src/executors` are plumbing. The planner and the `LLMCompiler` engine
(whose `join` step is the joiner) are found. The task fetching unit and executor are a scheduler and a tool runner
with no model call, so they are not on a map of agents and their three arrows stay missed (code recall 1.00).

**AutoSurvey.** Before, the only block was `APIModel`, the raw-HTTP client. Its request method is name-mangled
(`self.__req(...)`), and every `__x` method was treated like `__init__`, so climbing to the code that writes the
prompts stopped there. Its HTTP header strings also counted as prompt text. *Now* the outline writer's four steps, the
subsection writer and the judge are found, in order. A connectivity check in `main.py`
(`print(outline_writer.api_model.chat('hello'))`) used to make `write()` and `main()` agents too; it no longer does.
Refinement (`lce`) is a second prompted method inside the subsection writer: a class is split into steps only at three
or more prompted methods, so it stays folded into the drafting block.

**Self-Refine.** Each task's three classes (`*TaskInit`, `*Feedback`, `*TaskIterate`) ask the model through
`openai_api.OpenaiAPIWrapper.call(prompt=...)` from `prompt_lib`, a package that is not in the repository. *Now* a
provider-named wrapper package outside the project is a model call, so all three roles are found per task, and the
`while` loop in each `run.py` gives generator → critic → refiner → critic. The GPT-4V colab notebook's own loop left
the map with the notebook rule. Edge precision is 0.75 because the map also draws critic → generator, the loop
going back over the first attempt. The map is capped at 15 model callers, so two of the six tasks
(response generation, sentiment reversal) are left out.

**MACRec.** Found before and after: manager, analyst, searcher, reflector and interpreter. The README draws two
analysts; the code has one `Analyst` class answering both `UserInfo` and `ItemInfo`, so that box is `readme_only`.
The missed manager → reflector arrow is real in a run, but in code the reflector runs at the start of the *next*
`forward()` call (reflect, then interpret, then the manager loop), so the map draws reflector → interpreter → manager.

**memory-agent.** Perfect before and after: a two-node LangGraph graph.

**The AI Scientist.** Before, the map had one block, `q_agent`: a `QLearningAgent(lr=0.1, gamma=0.9, epsilon=0.1)`
from an example paper's generated experiment code, picked up by the "`*Agent(...)` with keywords" rule. That one block
also switched off the plain pass. *Now* a project `*Agent` class with no model, framework or prompt anywhere in its
file is not an agent. Three more shapes were missing:

- `perform_review()` takes its prompt as a parameter whose default is the module's reviewer template, so it looked
  like a forwarding helper;
- experiments and write-up run through aider: `coder = Coder.create(...)` in `launch_scientist.py`, then
  `coder.run(prompt)` inside `perform_experiments(idea, folder, coder, ...)`;
- the coder is handed to those functions as an argument, so no file both builds and uses it.

*Now* a template default is the function's own prompt, aider is a model library, and a client handed to a project
function as an argument is a client inside it. The whole pipeline is found in order: idea generation → novelty check →
experiments → write-up → review (→ improvement). The duplicate is `generate_next_idea` beside `generate_ideas`, and
edge precision is 0.57 because the open-ended variant (`experimental/launch_oe_scientist.py`) and the citation and
LaTeX-fix steps add real arrows the GIF doesn't draw.

## Changes on dev-refinement (general rules, no project named)

1. **Thin framework + plain model calls** (`static_scan.py`). When the framework pass finds only one or two agents and
   nothing wires them (no graph, crew, group chat, config agents or hand-offs), the plain-model-call pass still runs.
   Its agents in other files join the map (two or more needed) and run order links them.
2. **Tutorial names** (`static_scan.py`). A literal placeholder name (`my-assistant`, `agent1`, `test_bot`) is
   replaced by the file's name, or the factory's when the file name is generic.
3. **More model libraries and call shapes** (`call_sites.py`). Prompty / promptflow, aider `Coder`, provider-named
   wrapper packages outside the project, LangChain's `apredict` / `agenerate_prompt` / `generate_prompt`, parameters
   typed as models (and `self.x = param`), and clients handed to project functions as arguments.
4. **Prompt ownership** (`call_sites.py`). Prompt files (`*.prompty`, `*.jinja2`, `prompt*.txt`) and prompt
   parameters that default to a project template count as the function's own prompt; HTTP header dicts don't count as
   prompt text.
5. **Private methods and pings** (`call_sites.py`). Only true dunders (`__init__`, `__call__`) are skipped when
   following callers; a caller that only sends a short literal (`chat("hello")`) is a connection check.
6. **Library copies** (`call_sites.py`). Project classes named like a framework's own chain / executor classes, in
   files importing that framework, are plumbing.
7. **Non-LLM `*Agent` classes** (`static_scan.py`). A project `*Agent` class with methods but no model, framework or
   prompt words in its file, built without model keywords, is not an agent.
8. **Hand-over methods** (`call_sites.py`). A method that only calls one agent stands for it when linking run order.
9. **Notebook walkthroughs** (`static_scan.py`). Notebooks are treated like `examples/` when the package wires agents
   of its own.
10. **Builder-function subgraphs** (`static_scan.py`, `run_order.py`). `g = build_graph()` ending in `.compile()` is a
    compiled graph; graph ends and subgraph links are kept per builder function.
11. **Module-qualified calls** (`run_order.py`). `researcher.research(...)` on an imported module runs that module's
    function, in run order and as an agent call.

Tests: `tests/test_scan_set9.py` adds 10 made-up projects, one or more per rule. The full suite passes (188 passed,
5 skipped).

## Remaining failures and likely causes

- **Non-agent boxes in the drawing.** LLMCompiler's task fetching unit and executor (and, from set 8, ai-hedge-fund's
  portfolio and execution stages) are plain code. A map of model callers can't show them, so their arrows are lost.
  Drawing the functions that consume agent output as passive steps, behind a flag, is still the most promising next
  step.
- **Two-step classes.** AutoSurvey's drafting and refinement are two prompted methods of one class. Splitting at two
  would help here but has added noise elsewhere; a rule that splits only when the two prompts are different
  constants *and* the class's own driver calls them in sequence may be safe enough to try.
- **Order across calls.** MACRec's reflector runs at the start of the next `forward()`. Static run order sees only one
  call, not the loop of trials around it.
- **Multi-program repositories.** Reflexion (four experiment programs) and Self-Refine (one pipeline per task, capped
  at 15 blocks) keep strict precision down. Grouping agents by program folder would make these maps more readable.
- **Evaluation code beside the system.** Contoso's evaluators and The AI Scientist's open-ended variant are real model
  callers that the README leaves out (lenient precision 0.90-1.00).
